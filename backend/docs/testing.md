# Platform tests and checks

`./mvnw clean verify` runs unit tests, ArchUnit, PostGIS integration tests, formatting and JaCoCo reporting. Docker is mandatory for integration tests. `-DskipITs` is the explicitly reduced local run. CI uses the full run. Coverage HTML/XML is under target/site/jacoco and uploaded with reports; no arbitrary global threshold is imposed before feature code exists.

Extend PostgisIntegrationTest for application tests. It shares one container per JVM and imports a fixed UTC Clock (2026-11-16T12:00Z). Spring contexts may be shared; all SQL fixture factories create unique UUIDs. Keep database-mutating tests transactional with rollback, or use TransactionTemplate with rollback as SchemaIntegrityIT does. Do not truncate shared tables or enable parallel test execution without defining resource locks. HTTP calls run outside the caller's rollback transaction; use dedicated IDs/cleanup for persisted HTTP writes. Production application time must come from injected Clock, not Instant.now().

Fixtures supplies factories for users, businesses, locations, categories, offers, orders, payments and refunds, plus a catalog aggregate. TestFoundation.asUser(UUID, CLIENT|BUSINESS|ADMIN) scopes the current-thread SecurityContext and restores it in close(); it is not an HTTP JWT substitute. Controller tests can use Spring Security Test's `user(uuid).roles(role)` request postprocessor; actual JWT tests must use A's issuer and verification configuration.

ExternalServices creates an ephemeral-port WireMock server and success/failure stubs for payment/mail HTTP contracts. Configure each adapter's URL to `url()` and use try-with-resources. These test-only paths do not prescribe an external provider's API. No test calls real providers. Mail/payment adapters do not exist yet; feature teams add adapter-specific contract tests.

SchemaIntegrityIT verifies ownership FKs, stock bounds, payment uniqueness, financial retention and indexes. MigrationFailureIT upgrades V2 to V5 in an isolated temporary schema and checks a deliberately invalid migration names its source file. DemoDataIT validates isolated dev seeds and checks the main test database has no demo identities. Entity schema-drift checks run with ddl-auto=validate as feature entities are introduced; no reference release has been tagged yet, so V2 is the explicit upgrade checkpoint.

SearchIndexesIT records EXPLAIN (ANALYZE, BUFFERS) for selective ST_DWithin and ILIKE queries with 10,000 synthetic locations/offers and asserts actual index selection without disabling sequential scans. Its generated data rolls back. These tests demonstrate index usability, not application p95 latency guarantees; P22/P24 require real feature queries and workload baselines.

CI scans the built runtime image (including packaged Maven dependencies) using Trivy. Any CRITICAL finding, including one without an available fix, fails verification. The report is uploaded even on failure. HIGH findings are a release-review concern for P23; this gate implements P5's critical-vulnerability requirement. Updating the scanner database is part of each CI run; no CVE ignore list is supplied. Configure the required repository check and verify GHCR publication on main as maintainer follow-ups.
