## HTTP contract

Public: `GET /api/v1/categories`, `GET /api/v1/businesses/{id}`, `GET /api/v1/offers/{id}`, `GET /api/v1/offers/nearby`. Business routes require `ROLE_BUSINESS` and a UUID principal supplied by A's JWT filter. No authentication bypass or placeholder login was added. The JWT filter is not on main yet: merge A's work through the team's normal review process before an actual mobile login-to-catalog demonstration.

Business management: `GET/PATCH /api/v1/businesses/me`; `GET/POST /api/v1/businesses/me/locations`; `PATCH/DELETE /api/v1/businesses/me/locations/{id}`; `PUT /api/v1/businesses/me/location`; `GET/POST /api/v1/businesses/me/offers`; `GET/PUT/PATCH/DELETE /api/v1/businesses/me/offers/{id}`; `POST /api/v1/businesses/me/offers/{id}/pause` and `/resume`. Deletion returns 204, create returns 201. An offer belonging to another owner returns 404. Profile fields for rating and verification are read-only. Public profiles expose only the primary location's label, city and country, never precise coordinates or owner contact details.

Offer writes use `{title,category,description?,originalPrice,price,quantity,pickupStartAt,pickupEndAt,imageAsset,locationId?,currency?}`. Timestamps are ISO UTC; currency defaults to EUR. Category accepts the slug, frontend enum name, category UUID or exact display label. `imageUrl` is an alias of `imageAsset`; HTTP(S) URLs only. Location defaults to the owned primary location. PATCH merges omitted fields before applying the same validation as create. Invalid fields return 422 `VALIDATION_FAILED` with `{field,message}` entries; state conflicts return 409. `quantity` is total stock: edits preserve already reserved units and cannot reduce total below reservations. Responses include Flutter BusinessOffer keys plus additive `status`.

Discovery: `latitude`, `longitude`, `radiusKm` (default 1, max 50), `query`, `category`, `minDiscount` (percentage 0–100), `maxPrice`, `pickupBefore` (HH:mm, inclusive start-time cutoff in Europe/Bucharest), `pickupToday` (start date in Europe/Bucharest), `sort` (NEAREST, BIGGEST_DISCOUNT, LOWEST_PRICE, ENDING_SOON), `page` (default 0), `size` (default 20, max 50). Omitted coordinates fall back only to an authenticated CLIENT's consented saved location; otherwise 400 `MISSING_LOCATION`. Both coordinates must be supplied together. Only active, nondeleted, in-stock offers with a future pickup end are returned. Joined projections avoid N+1 queries; distance uses PostGIS geography and is rounded to two decimals in km. Detail without a search origin reports distanceKm=0; use nearby discovery for a measured distance.

Deal fields are immutable fetch-time snapshots with the six existing Dart enum values. **Frontend dependency:** `other` is present in the categories/business API but excluded from public Deal discovery and detail until the frontend owner adds/approves it. Do not silently relabel it as another category. Network image rendering also needs frontend wiring, as already identified by P20; no frontend files were changed here.

## Foundation compatibility and follow-ups

* No Flyway migration was added or edited. The P11 database check does not allow status DELETED. Soft deletion persists `deleted_at` and PAUSED, while the business API reports DELETED. Ask P for a forward migration if a persisted DELETED enum value is required; never edit V2 in place.
* P2's existing `OfferStockPort` has `void reserve` and `void release`. The adapter preserves this interface so C's existing branches/fakes still compile. `release` performs restoration; both methods require a caller transaction and lock the offer. **Outstanding B6 contract item:** a returned unit-price snapshot cannot be provided by the current void port. P/B/C must agree an additive shared snapshot contract before C can consume one through this port. Existing C branches currently read offer data separately; do not represent the snapshot requirement as completed.
* `UserRegisteredEvent` was aligned with the exact compatible five-field record on `origin/luca/auth-account-tickets`, retaining the existing two-argument constructor. The listener checks the persisted BUSINESS role, serializes duplicate events on the user row, and runs in a new transaction after commit (or for A's already-after-commit event). Coordinate-only registrations create a primary draft address with empty street/city and unspecified country ZZ. B3 must complete it before B7 can publish an offer. The event contains no postal address/country, so no real address is inferred.
* Primary-location changes lock the business row and flush demotion before promotion. Locations referenced by offers or historical orders cannot be physically deleted (409); deleting an unreferenced primary promotes another when available.
* Reconciliation runs every five minutes using a transaction-scoped PostgreSQL advisory lock. It expires ACTIVE/PAUSED/SOLD_OUT offers at the end of pickup, reconciles zero/restored stock, retains paused state and never deletes history. Counters/timers contain no personal data. The deployment must supply normal scheduler monitoring.
* See [media configuration and cleanup policy](media.md). The S3 adapter is implemented but has not been exercised against a real bucket. Platform operations must schedule the documented orphan sweep before production use.
